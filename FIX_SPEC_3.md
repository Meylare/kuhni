### B1. Исправление кнопки «−» в быстром степпере позиций (критично)

**Проблема.**
В `apps/web/src/lib/order-lines-stepper.ts` в функции `mergeOrAddPriceItem`:
```ts
const normalizedDelta = roundQuantity(Math.max(0.001, deltaQty));
```
При нажатии на кнопку **«−»** в модальном окне справочника цен передаётся `deltaQty = -1`. Из-за `Math.max(0.001, -1)` дельта принудительно превращается в `+0.001`! Каждый клик на минус прибавлял одну тысячную (например, кликнув 24 раза, пользователь получил `13.024 лист`).

**Решение.**
1. В `order-lines-stepper.ts`:
   - Поддержать отрицательные значения `deltaQty` (уменьшение количества).
   - Если итоговое количество `existing.qty + deltaQty <= 0`:
     - Строка удаляется из массива строк (действие `action: "deleted"`), возвращая удалённую строку в `affectedLine`.
   - Если количество остаётся $> 0$:
     - Выполнять нормальное вычитание с защитой от float-артефактов: `roundQuantity(existing.qty + deltaQty)`.
2. В `apps/web/src/hooks/useOrderLines.ts` (`handleStepPriceItem`):
   - Если результат степпера — `"deleted"`, удалять строку из базы данных через `deleteLineFromDatabase(lineId)` (или отменять таймер дебаунса и выполнять `.delete().eq("id", line.id)`).
   - Если результат — `"updated"`, продолжать дебаунс-синхронизацию обновлённого `qty`.
3. В `LinesSection.tsx`: убедиться, что быстрый степпер строки в смете также работает согласованно и при уменьшении до 0 удаляет позицию.

**Тесты (`order-lines-stepper.test.ts`):**
- Уменьшение количества на 1: при 5 листах и delta = -1 становится 4 листа.
- Уменьшение количества на дробную дельту не создаёт артефактов `0.001`.
- Уменьшение до 0 или ниже: строка корректно удаляется (`action: "deleted"`).
- Позиции нет в заказе и передана отрицательная дельта: заказ не изменяется.

**Как проверить на телефоне:**
1. Открыть любой заказ, нажать «+ Из справочника».
2. Нажать «+ 1» на позиции (количество стало 1).
3. Нажать «+» ещё 2 раза (количество стало 3).
4. Нажать «−» (минус) — количество должно стать ровно 2.
5. Нажать «−» ещё дважды — позиция должна удалиться из заказа, а кнопка вернуться в исходное состояние «+ 1».

### B2. Сброс и предзаполнение формы «⋯» (три точки) в справочнике цен (критично)

**Проблема.**
При клике на «⋯» (три точки) напротив позиции каталога вызывается `handleSelectPriceItem(pi)` в `apps/web/src/hooks/useOrderLines.ts`. Функция меняет `selectedPriceItem`, но **не очищает и не обновляет** поля формы: `pickerQty`, `pickerWaste` и `pickerComment`. Если ранее вводилось число (например, `10`), то для следующего выбранного товара в форме остаётся старое значение `10`.

**Решение (согласно ответу владельца: «текущее»):**
1. При вызове `handleSelectPriceItem(priceItem)` проверять, добавлена ли уже эта позиция в заказ:
   - **Если позиция уже есть в заказе:**
     - `pickerQty` заполняется **текущим количеством** этой строки (`String(existingLine.qty)`).
     - `pickerWaste` заполняется текущим процентом отхода (`String(existingLine.waste_pct * 100)`).
     - `pickerComment` заполняется текущим комментарием (`existingLine.comment || ""`).
   - **Если позиции ещё нет в заказе:**
     - `pickerQty` сбрасывается в `"1"`.
     - `pickerWaste` сбрасывается в дефолт (для кромки `globalParams.waste_edge_pct * 100`, для остальных `"0"`).
     - `pickerComment` сбрасывается в `""`.
2. Очищать `pickerError` в `null` при открытии формы новой позиции.
3. При нажатии «Сменить» внутри детальной формы возвращать пользователя в список без сохранения залипших данных.

**Тесты (`PricePickerModal.test.tsx` / `useOrderLines.test.ts`):**
- Клик по 3 точкам для нового товара открывает форму с `qty = "1"` и пустым комментарием.
- Клик по 3 точкам для товара, у которого уже в заказе 4 шт и отход 10%, открывает форму с `qty = "4"` и отходом 10%.
- После закрытия и открытия другого товара данные предыдущего не остаются.

**Как проверить на телефоне:**
1. Открыть справочник цен, выбрать позицию А (нажать «⋯»), ввести количество «7», нажать «Сменить» или закрыть.
2. Нажать «⋯» на позиции Б (которой нет в заказе) — в поле количества должно стоять «1», а не «7».
3. Для позиции, у которой в заказе уже есть «3 шт», нажать «⋯» — в поле должно стоять «3».

### B3. Устранение автозума Safari на iPhone (важно)

**Проблема.**
На iOS (Safari / WebKit), если у элемента ввода (`<input>`, `<select>`, `<textarea>`) размер шрифта меньше 16px, браузер при фокусе автоматически приближает (зумит) экран к этому полю и после завершения ввода не возвращает масштаб обратно. Это ломает вёрстку и заставляет пользователя вручную сжимать экран пальцами.

**Решение.**
1. В `apps/web/src/index.css` добавить глобальное правило для мобильных устройств:
   ```css
   @media (max-width: 768px) {
     input,
     select,
     textarea {
       font-size: 16px !important;
     }
   }
   ```
2. В `apps/web/index.html` проверить метатег viewport:
   ```html
   <meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover" />
   ```
3. Проверить, что все кнопки степперов, крестики очистки и поля поиска имеют минимальную область нажатия не менее $44 \times 44$ px (`min-h-11`).

**Тесты:**
- Прогон сборки `npm run build` и тестов интерфейса.
- Проверка отсутствия элементов ввода с шрифтом меньше 16px в мобильных медиа-запросах.

**Как проверить на телефоне:**
1. Открыть приложение в Safari на iPhone.
2. Тапнуть по поиску в каталоге, по вводу количества или по любому полю в параметрах.
3. Экран **не должен приближаться** (масштаб 1:1 сохраняется), клавиатура открывается без смещения страницы.

### B4. Расчёт сборки «по погонным метрам» (критично)

**Проблема.**
Владелец переключает режим сборки на «За метр» (`per_meter`), сохраняет настройки, но сумма сборки становится `0 ₸`.
**Причина:**
В `packages/calc` сборка по метрам считается строго через массив изделий заказа `orderItems` (`fixedAssemblyCost` перебирает `item.linearMeters`). Если пользователь не создавал отдельные карточки изделий в блоке «Изделия заказа» (например, считает единую кухню только по смете материалов), массив изделий пуст, и сборка превращается в 0 ₸. Кроме того, в аккордеоне параметров заказа нет поля ввода метража.

**Решение.**
1. **Поддержка прямого ввода метража на уровне заказа:**
   - В настройках заказа (`orders.settings`) поддержать поля:
     - `order_linear_meters`: число (погонные метры, точность до см, например `3.20`).
     - `order_kind`: тип изделия (`kitchen` по умолчанию или `wardrobe`).
2. **Логика в `buildCalculationInput` (`apps/web/src/lib/orders.ts`):**
   - Если в заказе заведены карточки в `orderItems` с ненулевым метражом — расчёт сборки суммирует метраж из них (как сейчас).
   - Если карточек изделий нет (или их суммарный метраж = 0), но в настройках заказа указан `order_linear_meters` — в `calcItems` передаётся синтетическое изделие: `{ kind: settings.order_kind || "kitchen", linearMeters: settings.order_linear_meters }`.
3. **Интерфейс в `OrderParametersAccordion.tsx`:**
   - При выборе «Режим сборки: За метр» (`per_meter`):
     - Если изделий нет: отображать поле ввода: **«Погонные метры изделия (м): [ 3.0 ]»** и переключатель типа (Кухня 35 000 ₸/м или Шкаф 25 000 ₸/м).
     - Если изделия уже заведены: отображать информационную плашку: *«Метраж берётся из изделий заказа: X.XX м (сумма: Y ₸)»* с кнопкой перехода к изделиям.
     - Если метраж равен 0: отображать предупреждение: *«⚠️ Укажите погонные метры, иначе сборка = 0 ₸»*.
4. **Синхронизация с живым предпросмотром:**
   - Изменение метража сразу же на лету пересчитывает сумму сборки в смете и нижней плашке.

**Тесты (`calc`, `orders.test.ts`):**
- Расчёт в режиме `per_meter` при наличии `order_linear_meters` в настройках заказа даёт точную сумму: $3.0\text{ м} \times 35\,000\text{ ₸} = 105\,000\text{ ₸}$.
- При наличии изделий метраж берётся из изделий.
- При отсутствии метров выдаётся корректное предупреждение.

**Как проверить на телефоне:**
1. Открыть заказ (без изделий).
2. Раскрыть блок «⚙️ Дополнительно (параметры)».
3. Выбрать «Режим сборки: За метр».
4. В появившемся поле ввести «3» м (Кухня).
5. Нажать «Сохранить параметры» (или посмотреть живой расчёт): в сводке сборка должна стать **105 000 ₸**, а цена заказа пересчитаться с учётом этой сборки.

### B5. Улучшение читабельности и компактности сметы заказа (важно)

**Проблема.**
Владелец: *«не удобно смотреть я имел в виду все меню когда ты заказ уже собрал. у тебя длинный не читабельный список всего что ты в заказ посчитал. надо придумать как сделать удобно для использования и читабельно»*.
Сейчас все категории («Материалы», «Фасады», «Цех», «Фурнитура» и т.д.) выводятся длинным сплошным списком. Когда позиций 20+, экран требует долгой прокрутки, ориентироваться тяжело. В нижней плашке маржа выводится с 3 знаками (`15,029 %`), что визуально перегружено.

**Решение.**
1. **Сворачиваемые категории с аккордеонами в `LinesSection.tsx`:**
   - Каждая категория становится кликабельным аккордеоном с чётким заголовком:
     `[▼ / ▶] ФАСАДЫ (3 позиции) — 145 000 ₸`
   - Возможность свернуть любую категорию одним тапом, чтобы спрятать ненужные детали.
   - В шапке раздела добавить быстрые кнопки: **«Свернуть все» / «Развернуть все»**.
   - По умолчанию категории открыты, но пользователь может свернуть просмотренные.
2. **Компактные чипсы-подытоги категорий (Category Overview Bar):**
   - Вверху раздела «Позиции и затраты» расположить компактную горизонтальную ленту чипсов с подытогами:
     `[Фасады: 145 000 ₸] [Цех: 84 653 ₸] [Материалы: 56 000 ₸] ...`
   - Тап по чипсу плавно скроллит к этой категории и разворачивает её.
3. **Оптимизация высоты карточек позиций на мобильных экранах:**
   - Сделать компактный однострочный layout строки на мобильных:
     - Верхняя строка: Название позиции (полужирный), бейдж («ручная»), общая сумма справа крупно.
     - Нижняя строка: степпер `[−] 3 м² [+]`, цена за единицу `× 38 000 ₸`, кнопки действий компактно в правом углу.
   - Уменьшить пустые вертикальные отступы, чтобы на экран смартфона помещалось в 2 раза больше позиций.
4. **Округление маржи в нижней панели (`SummaryBar.tsx`):**
   - Отображать маржу с 1 десятичным знаком: например, `15,0 %` вместо `15,029 %`. Если число целое — `15 %`.

**Тесты:**
- Тесты на сворачивание/разворачивание категорий в `LinesSection.test.tsx`.
- Форматирование процентов в `parameters.test.ts`.

**Как проверить на телефоне:**
1. Открыть заказ с несколькими категориями (фасады, цех, материалы).
2. Нажать «Свернуть все» — список позиций мгновенно сожмётся в аккуратный структурированный список категорий с суммами.
3. Развернуть только категорию «Фасады» — виден удобный компактный список только этих позиций.
4. В нижней панели маржа отображается красиво: `15 %` или `15.0 %`.
