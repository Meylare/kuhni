# Система расчёта и учёта заказов мебели (kuhni)

Система расчёта себестоимости, ценообразования и план-фактного учёта для производства корпусной мебели.

## Стек технологий

- **Фронтенд:** React 18, TypeScript, Vite, Tailwind CSS (Mobile-first PWA).
- **Бэкенд:** Supabase (PostgreSQL, Row Level Security, RPC-функции, Auth).
- **Расчётное ядро:** Чистый TypeScript-модуль `packages/calc` (`@kuhni/calc`) без обращений к базе данных, покрытый модульными тестами Vitest.

## Ключевые правила и форматы данных

- **Валюта:** тенге (KZT), только целые числа.
- **Количества:** точность до 3 знаков после запятой (`numeric(12,3)`).
- **Погонные метры:** точность до сантиметра (`numeric(8,2)`).
- **Иммунитет заказов:** зафиксированные версии расчёта неизменяемы. Изменение глобальных параметров не меняет цифры сохранённых заказов.

## Эталонный расчёт (Benchmark)

Для эталонной кухни 3 погонных метра на базовом наборе позиций и стандартных параметрах (маржа 18%, сборка 14.5%, технолог 4%, отход кромки 10%):

- **Режим «Рассчитать цену» (`quote`):**
  - Расчётная цена договора: **862 000 ₸**
  - Себестоимость: **706 210 ₸**
  - Маржа: **155 790 ₸** (**18,07%**)
  - Сборка: **124 990 ₸**, Технолог: **34 480 ₸**
- **Режим «Проверить договор» (`check_contract`, 850 000 ₸):**
  - Себестоимость: **703 990 ₸**
  - Маржа: **146 010 ₸** (**17,18%**)
  - Предупреждение: *«договор ниже минимальной цены 862 000»*
- **План/Факт:**
  - Сумма строк статей сметы плана строго равна `cost_total` (**706 025 ₸**).
  - При договоре 800 000 ₸, расходах 500 000 ₸ и предоплате 400 000 ₸:
    - Фактическая прибыль: **+300 000 ₸** (рентабельность 37.5%).
    - Оплачено: **400 000 ₸**, остаток долга: **400 000 ₸**.
    - Кассовый баланс: **−100 000 ₸**.

## Интерфейс и возможности (UI v2)

- **Этапы жизненного цикла заказа:**
  - **«Смета»:** быстрый ввод позиций со встроенными степперами количества, группировка по изделиям, шаблоны типовых наборов.
  - **«Договор»:** ввод согласованной суммы, расчёт маржинальности, фиксация договорной версии (`contract_baseline`).
  - **«Факт»:** план-фактная сверка расходов по категориям, учёт переделок и оплат.
- **Быстрый ввод и шаблоны:**
  - Каталог остаётся открытым при добавлении; степперы (− / +) прямо в строках каталога и заказа; блок «Недавние» (8 популярных позиций).
  - Шаблоны изделий с возможностью быстрого применения актуальных цен прайса (`TemplatesPage`).
- **Безопасность и отмена действий:**
  - Отложенное удаление на 6 секунд с кнопкой «Отменить» (Undo toast) вместо блокирующих диалогов.
  - Дублирование позиций и изделий одним тапом.
- **Производительность (PWA & Code Splitting):**
  - Ленивая загрузка маршрутов (`React.lazy`), начальный JS бандл всего **~24 КБ** (при таргете M5 <= 350 КБ).
  - Автоматическое определение обновлений Service Worker с ненавязчивым баннером «Обновить».

## Команды

```bash
# Установка зависимостей
npm install

# Проверка линтером (oxlint)
npm run lint

# Проверка типов ядра расчёта
npm run typecheck -w @kuhni/calc

# Запуск тестов (calc + web)
npm test

# Сборка веб-приложения
npm run build
```

## CI / Автоматизация

В проекте настроен GitHub Actions workflow (`.github/workflows/ci.yml`), который при каждом push и pull request в ветку `main`:
1. Запускает проверку линтером (`npm run lint`), проверку типов, модульные тесты (`npm test`) и сборку приложения (`npm run build`).
2. Поднимает тестовый локальный инстанс Supabase и прогоняет весь набор SQL-тестов из директории `supabase/tests/*.sql` через `psql` с флагом `ON_ERROR_STOP=1`.
